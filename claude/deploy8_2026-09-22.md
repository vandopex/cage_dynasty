## §5 v1.2 candidates added by #8

Candidates for deploy_procedure.md v1.2; not procedure until landed.

* Every PA-console `send_input` should use `curl --data-urlencode` (or an equivalent that URL-encodes `&`, `?`, `=`, `+`, spaces). Never `-d`. The `&&` in shell commands otherwise silently truncates the payload at the first `&`.
* Every `get_latest_output` poll body should be written to a per-iteration file (e.g. `/tmp/poll_<console>_<n>.txt`). Console garble windows are reconstructable only if the raw JSON survives to disk; piping to `python3 -c` inline loses the record.
* Step 3 command block should include a pre-reload error.log fetch as the step-3 baseline (`/tmp/error_baseline.log`). Step 11 then compares against a real file, not a post-hoc line count. This was already an owed v1.2 candidate before #8; #8 bit it.
* Gates-table rows in every filing should cite the printed output the row rests on (log path + line number, or command + printed marker). "Because I said so" narrative rows without an evidence column create the class of drift #8 §4(a) documents.
