## 1. MECHANISM

**API-driven, no browser typing this pass.** First time cc has driven
a deploy end-to-end via the PythonAnywhere HTTP API. The two deploy
mechanisms recorded in prior filings — deploy.sh webhook (interim, half-
dead) and console git pull + Web-tab reload (deploy #3) — remain valid
fallbacks; this is a third option, now the standing procedure (see
CLAUDE.md deploy-discipline section, edited this ship).

Recipe:
- Token in `~/.pa_token`, chmod 600, outside git. Read inline as
  `T=$(cat ~/.pa_token)` inside each `bash -c '...'` invocation so
  the token never appears in a shell log line and never in a script
  file. Bash-inside-bash-c keeps the expansion local; the outer log
  shows `$T` literally. Residual: the token IS in `curl` argv per
  call (fully expanded before `execve`, visible to `ps` during the
  call). `curl -H @file` (header from a file or stdin) closes that
  residual; not applied this pass — noted for §5.
- Base URL: `https://www.pythonanywhere.com/api/v0/user/vandopegaming`.
- Auth header: `Authorization: Token $T`. Every call prints `HTTP_STATUS:
  %{http_code}` from curl `-w`. Response bodies contain no secrets.

Flow: (1) auth check `GET /webapps/` → 200 with domain listed.
(2) `GET /consoles/` → pick a started bash console. (3) `send_input/`
+ `get_latest_output/` to run any shell command. (4) `POST
/webapps/vandopegaming.pythonanywhere.com/reload/` → 200. (5) Files
API `GET /files/path/<abs-path>` to fetch any file for verification
without needing a console at all.

Recorded caveat, worth its own docket **CONSOLE-STARTED1**: consoles
that exist in the API listing but have not been loaded in a browser
recently return HTTP 412 `"Console not yet started. Please load it
(or its iframe) in a browser first"` on both send_input/ and
get_latest_output/. Two consoles were listed at deploy time; console
47103182 (working_dir set to cage_dynasty_web/) 412'd, console
47055546 (working_dir null but recently browser-opened, prompt showed
`~/cage_dynasty (main)$`) worked. Fallback: pick the responsive
console; if none responds, `POST /consoles/` to create a new one and
load it once in the browser before use. Not blocked here — one of two
started; noted for the standing procedure so future deploys pick the
started one instead of the more-recently-created one.
