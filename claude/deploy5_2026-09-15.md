### Two upgrades, why they matter

**Step 0 warm-check.** Before this ship the warm-check was implicit —
`get_latest_output` was called at step 3, so a 412 discovered there
had already burned steps 1 and 2. Moving it to step 0 costs nothing
(one API call the flow already makes) and makes cold-console failures
cheap. Recorded here as the standing procedure.

**File hash as the gate.** A grep proves that four strings exist in
the running file. It does not prove the running file is the file we
committed — a grep can return empty because the string was renamed,
because the pattern was mis-escaped, or because the file was
truncated. sha256 against the local committed copy proves the whole
file end-to-end. Marker greps are still useful as human-readable
sanity (`this shipped body has these four guard-code fragments in it
at these line numbers`), but the hash is the gate that catches a
phantom deploy. Together with the log-timestamp half of the triad
(file-on-disk + process-imported), this is a two-way proof of what
uWSGI is actually running.
